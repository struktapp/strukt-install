# 1.1.0 — Add new:dev command

## What changed

- Added `new:dev <app_name>` to install the Strukt skeleton and an
  explicit package list from GitHub `master.zip` archives.
- Added a `[dev]` section to `strukt.ini` for the GitHub organization, branch,
  skeleton, cache directory, and package slugs.
- Extracted packages are cached under `~/.cache/strukt/<branch>/` and reused on
  later runs; pass `--refresh` to re-download them. They are registered as
  Composer path repositories with symlinks enabled, while Packagist remains
  available for third-party dependencies.
- Extracted `composer.json` files are rewritten to use `dev-master` for the
  package version and all `strukt/*` requirements, with `minimum-stability`
  set to `dev` so `composer install` does not need an unsupported stability
  flag.
- Seeds `cfg/cmd.ini` from the installed framework template before running the
  post-create script, so `app:make` is discoverable in GitHub archives that do
  not ship a generated `cfg/` directory.
- Passes the requested application name to `app:make` to avoid an interactive
  prompt during `composer run-script`.
- Relinks the project-level `strukt` and `xhttp` stubs to `vendor/bin` after
  Composer installs the application.
- Added a self-contained test runner and `composer lint` / `composer test`
  scripts.

## Why

Development work often needs the unreleased `master` versions of all Strukt
packages without cloning each repository or losing Packagist resolution for
third-party libraries.

## Documentation touched

- `README.md` documents the new command.

## Tests added or updated

- `tests/DevInstallerTest.php` covers configuration normalization,
  archive URLs, requirement rewriting, path repository registration, and
  archive extraction.

## Public API impact

- New command: `new:dev`.
- New classes: `Strukt\Installer\DevInstaller` and
  `Strukt\Installer\Command\InstallerDev`.
