# 1.0.0 — Rewrite installer for new console and process

## What changed

- Rewrote `bin/strukt` to use `Strukt\Console\Runtime\Application` with
  command discovery from `src/Strukt/Installer/Command`.
- Rewrote `Installer`, `PackageInstall`, and `SelfUpdate` commands to
  implement `Strukt\Console\Runtime\CommandInterface` and use the new
  docblock-driven command format.
- Updated argument and option access to the new `execute(array $arguments,
  array $options)` signature.
- Replaced removed `Strukt\Console\Color` usage with plain output streaming.
- Updated composer constraints to `strukt/console` v2.0.0 and
  `strukt/process` v1.0.0, PHP >= 8.2, and PSR-4 autoloading.
- Replaced `Strukt\Fs::rm` with a native `unlink()` for `composer.lock`.

## Why

The installer still targeted the legacy console/process APIs, which no
longer exist in `strukt4`.

## Documentation touched

- `README.md` (unchanged content).

## Tests added or updated

- None. Validated with `php -l` and command discovery/help.

## Public API impact

- Command entry point and command class signatures changed to the new
  console runtime. Command names remain `new`, `add`, and `update:me`.
